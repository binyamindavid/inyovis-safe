# Duplicate review rules

Exact duplicates use the server's verified SHA-256 within an archive. Their sessions retain separate submissions and receipts, while newly received duplicates share one stored original, document and processing job. Migration 17 folds old duplicate stored-object references into a canonical object but leaves historical documents, revisions, receipts and download URLs intact. Private unreferenced keys remain for the inventory and cleanup work in #30.

Likely candidates require **distinct stored originals** and two cleared, Ready documents with current confirmed invoice revisions. Both revisions must link to the same archive supplier and have the same nonempty printed document number, civil issue date, exact numeric total and currency. The printed supplier names remain visible; they do not establish identity. A document without a linked supplier is ineligible, even if its printed supplier name matches. Missing comparison values are ineligible. Drafts never enter matching. Matching uses the exact stored printed number, including punctuation and leading zeroes; no fuzzy normalization is applied.

One row exists per unordered document pair in an archive. The row stores the two compared revision IDs. A later confirmation marks prior comparisons stale and queues a fresh comparison only if the new confirmed values still match. A reviewer decision records its actor, time, choice and revision IDs; the archive audit retains earlier decisions if a later confirmation reopens a pair. Retrying the same decision by the same actor returns its saved result. Conflicting concurrent decisions yield one winner and one conflict. Both originals and all submissions remain untouched; this workflow has no deletion action.
